# 業務規格與驗收資料

**本文件是判定正確性的來源。費率、服務組合與郵件資料皆為教學虛構，不代表中華郵政實際規範。** 不可為了讓測試通過而修改本規格。

## 既有功能

函式：`calculate_fee(weight_grams: int, service: str) -> int`。

- 重量必須是 1–20,000 公克的整數，含上下限；布林值不算整數。
- 1–1,000 公克為 60 元；超過後每 1,000 公克加 10 元，不足一級距也按一級距計。
- `standard` 一般不加價；`registered` 掛號加 20 元。
- 不合法重量或服務以 `ValueError` 明確回報，不回傳 0 或成功結果。

## API 契約

`POST /api/quote`，`Content-Type: application/json`：

```json
{"weight_grams": 1000, "service": "express"}
```

成功為 HTTP 200：

```json
{"fee": 90, "currency": "TWD"}
```

非法輸入為 HTTP 400，包含非空白 `error`，不得包含 `fee`：

```json
{"error": "重量必須介於 1 到 20,000 公克。"}
```

前端負責把欄位文字解析成整數數值。API 與核心函式不接受字串 `"1000"`、浮點數、布林值或缺少的重量；服務必須為合法字串。前端驗證不能取代後端驗證。壞掉的 JSON、非物件 JSON 或錯誤 Content-Type 也應回傳 400。

## Lab 2 UI/UX 契約

- 重量欄位有 label、單位、合法範圍；錯誤與欄位關聯，不只用顏色表示。
- Tab、Enter 可完成試算，焦點清楚；375px 寬度下主要頁面無水平捲動。
- 送出中避免重複請求；成功、HTTP 錯誤及網路失敗後均恢復操作。
- 變更輸入後，舊報價應清除或標示失效，不得誤當成新輸入的報價。
- 保留 API、DOM id 與 RPA 模擬頁，不加入新 UI 框架。
